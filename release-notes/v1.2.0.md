## What's new in LocalDoc Finder 1.2.0

### Better search results
- **File names count.** Typing a file's name finds it first, even if its text never mentions those words. Names are split on `_`, `-`, `.`, capital letters and numbers, so "tax report 2023" finds `Q3_TaxReport2023.pdf`. Small typos are forgiven ("recipt" finds `Receipt_Amazon.jpg`).
- **Smarter ranking.** Files with all your words beat files with some of them, and the exact phrase beats scattered words. Plurals match ("invoices" finds "invoice"), and the word you're still typing matches as you type.
- **Whole words only.** Searching "art" no longer matches "start" or "party".
- **Less noise.** "Similar meaning" results only appear when they clearly stand out, so unrelated files no longer fill the list.
- **One result per file**, with the best-matching passage as the excerpt and a count of how many places in the file matched.
- **See why something matched.** Each result says *File name*, *Exact phrase*, *All words*, *Some words*, *Text in image*, *Photo details* or *Similar meaning*, plus the PDF page.
- **Search operators (optional):** `"exact phrase"`, `-word` to leave files out, `name:word` for the file name only, and `ext:pdf` or `type:image` for one file type (`ext:pdf` on its own lists all your PDFs, newest first).

### Text in pictures and scanned PDFs
- **Photos, screenshots and receipts are now searchable by the text in them**, using on-device text recognition (English and other Latin-script languages). The recognition model is built into the app: nothing is downloaded and no picture leaves your phone.
- **Scanned PDFs** with no text layer are read the same way (first 12 pages), instead of being findable only by name.

### More file types
- **Word `.doc`, Excel `.xls` and `.xlsx`, and PowerPoint `.ppt`** files are now read properly. Before, the older formats were indexed as unreadable characters and `.xlsx` was not readable at all.
  - Spreadsheets are indexed sheet by sheet, one line per row (for example `Rent | 1200`), including formula results.
  - Presentations include slide text, text boxes and speaker notes.
  - Files with the wrong extension still work: a `.doc` that is really RTF, an `.xls` exported by a bank as an HTML table or CSV, or a renamed `.docx`.
- `.pptx` slides are now read in the right order (slide 10 after slide 9).

### After updating
Run **Start indexing** once. Pictures, scanned PDFs and Office files indexed by an earlier version are read again on that run, so their new text becomes searchable. Automatic folder monitoring only picks up new or changed files.

### Known limits
- Password-protected Office files and very old formats (Word 6 / Excel 95) are skipped.
- Dates in `.xls` spreadsheets appear as Excel date numbers.
- Text recognition reads Latin-script languages only.

### Development notes
- New `engine/search` package: `QueryParser`, `TextMatch`, `SearchRanker` and `MatchSummary`. `HybridSearchEngine` gathers candidates from full-text search (all words first, then any word), from every file name, and from vector similarity. Vector scores are measured against the whole collection for each query, and the vector scan now loads only the vectors, not chunk text.
- New `engine/office` package (plain Kotlin, no Apache POI): `CompoundFile` (OLE2), `LegacyWordExtractor`, `LegacyExcelExtractor`, `LegacyPowerPointExtractor`, `XlsxExtractor`, `RtfExtractor`, plus format detection from file contents.
- OCR with ML Kit `text-recognition` 16.0.1 (bundled model) in `ImageTextRecognizer`. Chunk metadata gains `ocr=1` and `office=1` flags, so older entries are re-read once. No database schema change.
- Removed the hard-coded "Colorado / Rocky Mountains" text that was added to some image descriptions.
- New tests: `SearchRankerTest` and `OfficeExtractorsTest`, with LibreOffice-written `.doc`/`.xls`/`.ppt`/`.rtf` fixtures.
